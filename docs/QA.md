# 0.1.2 Preview 折叠交互与操作面板

## 根因与完成标准

0.1.1 用 article 的 qb-collapsed class 驱动原文隐藏。真实 X 在鼠标移入时替换完整 className，清掉折叠类，原生内容与占位同时进入横向 flex，导致文字挤成竖排。上一版只验证了静态折叠和挂载宽度，没有覆盖此交互，验收不充分。

新版用扩展独立的 data-qb-collapsed 属性驱动隐藏，不更改 X 的原生 className。折叠后经历真实悬停仍须隐藏原文，展开须恢复原节点与正文宽度，节点复用不得继承上一条的折叠状态。

# 0.1.1 Preview 回归验收

更新：2026-10-18。旧版记录保留在下方，不把其构造样例分数当作新版准确率。

## 根因与修复

1. 真实 X 的 article 是横向 flex，旧版把宽度 100% 的插件宿主作为第二个横向子元素插入，挤压了原文。原模拟页使用 block article，没有复现宿主布局。新版正常状态挂在原生内层纵向容器里；折叠时将占位独立放回 article，隐藏原内容；展开保留节点身份。
2. 页面 URL 对应的是焦点帖，不一定是原帖。旧版将焦点帖强制当主帖、祖先帖标为未知。新版根据可见回复链区分原帖、祖先回复和焦点回复，推荐边界外不插入选择按钮。
3. 原设置只存密钥，测试入口要求用户填样例，完成状态不清楚。新版一次点击测试内置样例并保存；失败保留旧连接和未保存输入。

## 本次证据

- 自动测试 37 项通过。先添加回归用例，确认旧代码在布局容器和回复详情分类上失败，再修正。
- 真实 X 页面上，以用户截图对应的三个会话节点做前后对照：原文宽度 518 / 518 / 566 px；旧挂载方式为 398 / 318.42 / 366.42 px；新版恢复 518 / 518 / 566 px。新版对三个节点分别提交 post / reply / reply 类型。此项是在真实 X DOM 中注入生产内容脚本，模型输出使用明确的布局测试替身，不是已安装扩展的端到端认证验收。
- 浏览器原生 flex 模拟页：疑似 AI 回复自动折叠，原内容计算样式为 display:none；人工标记 AI 后立即折叠，后续其他回复请求附带 1 条样本。
- 集成测试执行真实设置 UI → 实际后台消息处理器 → 生产 Jev 协议适配器（HTTP 替身）→ 内容脚本自动折叠 → 人工非 AI 标签 → 后续请求样本。验证不填样例即可连接、无效新密钥不会覆盖原连接、密钥不回传、展开后挂载位置正确。
- 真实 Magpie/Jev：内置连接样例通过，返回 jev-1.13.0；增加一条“谢谢，已经解决了”的人工非 AI 样本后，后续请求确实附带样本。新短回复返回 AI 20%、低信息量 15%，共 2 次实际请求。这里只证明请求与结果链路，不证明个性化准确率提升。
- 人工样本最多 40 条；每次最多 3 条正例 + 3 条反例；增删样本清除旧缓存；本地样本不随内容脚本快照返回；删除/清空与标记顺序已测试。

完整用户 Chrome 安装、后台休眠唤醒、真实 X 原生拉黑、TypeSafe 官方直连以及判断质量评估仍未覆盖。真实页面布局测试、隔离集成测试和实际安装运行是不同边界。
