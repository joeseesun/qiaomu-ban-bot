# 0.1.2 Preview 折叠交互与操作面板

更新：2026-10-18。

## 根因与完成标准

0.1.1 用 article 的 qb-collapsed class 驱动原文隐藏。真实 X 在鼠标移入时替换完整 className，清掉折叠类，原生内容与占位同时进入横向 flex，导致文字挤成竖排。上一版只验证了静态折叠和挂载宽度，没有覆盖此交互，验收不充分。

新版用扩展独立的 data-qb-collapsed 属性驱动隐藏，不更改 X 的原生 className。折叠后经历真实悬停仍须隐藏原文，展开须恢复原节点与正文宽度，节点复用不得继承上一条的折叠状态。

## 本次证据

- 在用户截图对应的同一条真实 X 回复上注入 0.1.1 生产脚本，以内存消息替身处理人工标记（无模型请求、不写用户扩展存储）。捕获鼠标移入后 X 移除 qb-collapsed，原文 display 从 none 变为 flex，帖子高度从 54.59 px 变为 1858 px；截图复现同样的竖排。
- 同页注入 0.1.2 生产脚本，点击机器人图标标记 AI；连续 3 轮真实鼠标移出/移入，捕获原生 className 变化，但原文 display 始终为 none，折叠高度 46 px。点击展开后正文宽度恢复为 518 px（与原始宽度一致），原生节点身份保留，工具条回到原生内层。
- 40 项自动测试通过。新增 className 重写回归在旧版先失败（原文错误显示 flex），修复后通过；覆盖已折叠节点复用、人工标记后的 class 重写、概率直接显示、图标无障碍名称和 Escape 关闭面板。
- 浏览器模拟页加入原生 hover className 完整替换。浅色 600px 会话面板、深色 360px 窄屏均查看实际截图；窄屏 scrollWidth = viewport = 360px，面板宽 326px，全部按钮在面板边界内。
- 图标从 lucide 1.59.0 按需打包，使用本地 SVG，无远程脚本；许可随安装包附带。模型协议、密钥与人工样本存储逻辑没有变更。

本次真实页面验证的是生产内容脚本和原生 X 悬停/布局，后台消息为替身；不能替代用户 Chrome 已安装扩展的完整认证、后台休眠和跨标签页验收。没有在真实 X 执行拉黑、点赞、回复或发送；没有把布局测试分数当作作者判断。模型接入证据沿用下方 0.1.1 记录。

# 0.1.1 Preview 回归验收

更新：2026-10-18。旧版记录保留在下方，不把其构造样例分数当作新版准确率。

## 根因与修复

1. 真实 X 的 article 是横向 flex，旧版把宽度 100% 的插件宿主作为第二个横向子元素插入，挤压了原文。原模拟页使用 block article，没有复现宿主布局。新版正常状态挂在原生内层纵向容器里；折叠时将占位独立放回 article，隐藏原内容；展开保留节点身份。
2. 页面 URL 对应的是焦点帖，不一定是原帖。旧版将焦点帖强制当主帖、祖先帖标为未知。新版根据可见回复链区分原帖、祖先回复和焦点回复，推荐边界外不插入选择按钮。
3. 原设置只存密钥，测试入口要求用户填样例，完成状态不清楚。新版一次点击测试内置样例并保存；失败保留旧连接和未保存输入。

## 本次证据

- 自动测试 37 项通过。先添加回归用例，确认旧代码在布局容器和回复详情分类上失败，再修正。
- 真实 X 页面上，以用户截图对应的三个会话节点做前后对照：原文宽度 518 / 518 / 566 px；旧挂载方式为 398 / 318.42 / 366.42 px；新版恢复 518 / 518 / 566 px。新版对三个节点分别提交 post / reply / reply 类型。此项是在真实 X DOM 中注入生产内容脚本，模型输出使用明确的布局测试替身，不是已安装扩展的端到端认证验收。
- 浏览器原生 flex 模拟页：疑似 AI 回复自动折叠，原内容计算样式为 display:none；人工标记 AI 后立即折叠，后续其他回复请求附带 1 条样本。
- 集成测试执行真实设置 UI → 实际后台消息处理器 → 生产 Jev 协议适配器（HTTP 替身）→ 内容脚本自动折叠 → 人工非 AI 标签 → 后续请求样本。验证不填样例即可连接、无效新密钥不会覆盖原连接、密钥不回传、展开后挂载位置正确。
- 真实 Magpie/Jev：内置连接样例通过，返回 jev-1.13.0；增加一条“谢谢，已经解决了”的人工非 AI 样本后，后续请求确实附带样本。新短回复返回 AI 20%、低信息量 15%，共 2 次实际请求。这里只证明请求与结果链路，不证明个性化准确率提升。
- 人工样本最多 40 条；每次最多 3 条正例 + 3 条反例；增删样本清除旧缓存；本地样本不随内容脚本快照返回；删除/清空与标记顺序已测试。

完整用户 Chrome 安装、后台休眠唤醒、真实 X 原生拉黑、TypeSafe 官方直连以及判断质量评估仍未覆盖。真实页面布局测试、隔离集成测试和实际安装运行是不同边界。

# 0.1.0 Preview 验证记录

更新：2026-10-18。此记录区分模型请求、代码测试、浏览器模拟页面和安装后的完整真实流程。

## 已验证

- `npm run package`：26 项自动测试通过，Chrome MV3 构建与 ZIP 打包成功。
- 核心策略：阈值/模式/名单优先级、异常响应不折叠、热帖数据门槛、缓存上下文与版本键。
- 后台引擎：同请求去重、并发与日预算、配置变更后拒绝旧结果、429 冷却、缓存/反馈、并行名单写入、密钥不随快照返回、换服务商清除旧密钥。
- 消息入口：设置页跳转 hash 后仍可保存；其他扩展、非 X 页面和子帧没有管理权限。
- DOM：主帖/回复/祖先/推荐区别、引文排除、本地化数字、原主帖被虚拟列表移除后保留上下文。
- 内容脚本：展开保留原节点；暂停恢复原文；复用节点不应用旧结果；手动保留优先于重复折叠；拉黑入口只到确认。
- 浏览器模拟页：疑似 AI 折叠、同文折叠、值得一读、热帖概率、展开；点击 X 屏蔽入口后模拟确认打开，实际屏蔽计数仍为 0。
- 浏览器设置页：浅/深色、400px 弹窗、360px 模型表单；无横向溢出，密码框聚焦无尺寸跳变。
- 实际 X 页面只读检查：成功提取一个主帖及 16 条回复，主帖与回复类型、作者和上下文关联正常。未对该页用户执行屏蔽或公开标记。

## 真实模型调用

经乔木 Magpie 使用生产代码中的 Jev 适配器调用，返回实际模型 `jev-1.13.0`。密钥仅从本机既有配置进入进程内存，没有写入源码、报告或安装包。

以下全部是构造文本，不是带标签的独立数据集，**不能据此推导准确率**。

| 样例 | AI 概率 | 低信息量 | 90% AI 模式结果 |
| --- | --- | --- | --- |
| 明确助手套话 | 92% | 88% | 折叠 |
| 具体人工风格纠错 | 14% | 14% | 保留 |
| 简短致谢 | 22% | 82% | 保留 |
| 引用 AI 表达讨论 | 37% | 34% | 保留 |
| 试图命令判断器输出固定答案 | 76% | 90% | 保留，并标低信息量 |
| 空泛夸赞 | 74% | 93% | 保留；低信息量模式会折叠 |

上述 6 次回复请求约 317–1,031ms/次；这是本次环境观测，不能承诺他人网络延迟。

热帖样例：构造一个发布约 1 小时、3,200 浏览、128 赞、32 回复、15 转帖的帖子，模型给出 24 小时达 10,000 浏览的概率 18%，请求约 898ms。这里只证明接口返回有效概率，不证明预测准确。
