Qiaomu X Helper 0.5.0 — reviewer notes

Purpose: assist the user's X reading and expression workflow: reversible reply filtering, bookmarks/search, reply drafts, and a local article editor with optional AI research and images. All final X publication/replies are user-confirmed.

No developer credentials are embedded or required for basic features. Do not use a production developer API key for review.

1. Load the package and open extension settings. Turn reply filtering off. Open Writing, create an article, enter text, switch Markdown mode, reload and verify persistence. Export Markdown. This requires neither login nor key.
2. Open model settings. Writing, Images, Web search, Image sources and Reply classification are separate sections. Add a service with your own supported credentials; the extension requests the relevant origin on save. A successful model list is not a generation claim. Changing a URL clears the old key. Jev uses typed decision endpoints, not chat completions.
3. In a writing draft, open AI. Enter a request using your configured writing service. Proposed changes are applied only after you accept the corresponding card. DeepSeek defaults to Flash.
4. Configure DeepSeek Search/Fetch or Brave Search using your own service credentials. Enabling search allows bounded tool calls with visible source links. Brave additionally reads public HTTPS pages and therefore requests optional HTTPS site access. Cookies, local-network URLs and redirects are not used for public page reading.
5. Open the gallery, upload a non-private image and insert it into an article. The file remains local unless you explicitly send it to a model or X. Optional Unsplash search requires its own Access Key or configured HTTPS proxy. Image rights remain the user's responsibility.
6. With a configured image provider, request a small image. Close the AI sidebar and reopen the gallery task tab; the offscreen document holds the running request. It processes Blob data, not hidden web browsing. Browser restart/interruption does not silently resubmit a paid task.
7. Local Codex image generation is optional and requires a compatible installed helper, logged-in Codex and registration of this extension's ID. The optional nativeMessaging permission is requested only when the user chooses that mode. Protocol actions are explicitly allowlisted to image status/start/poll/read/cancel. No helper is bundled or required for other features. See docs/LOCAL-HELPER.md for current compatibility limits.
8. Sign into a test X account. Open bookmarks and scroll normally: only already-loaded bookmarks are saved; pause is available. Search, add notes/tags, export Markdown. No private X API or automatic scrolling is used.
9. Add a post to the reply inbox, write a local draft, then choose Fill X reply box. The extension does not click Send. Contacts and local reply records are account-separated.
10. If the test account has X Articles, choose Publish to X in a nonempty writing draft. It opens X and fills a draft with text/media. There is no platform menu and no final Publish click. X account feature restrictions still apply.
11. Optional reply classification may be tested with your own supported Jev service. Unknown/invalid responses fail open. Human/AI reports are uncertain content judgments, not identity verification; account blocking is never automatic.
12. Configuration backup excludes API keys by default and always excludes OAuth sessions. Web/image source settings are included; articles/images/bookmarks have separate export paths. Community subscription and contribution are off by default, require an invitation and are not needed for the extension.

Data: extension storage.local and IndexedDB, no Chrome Sync. Optional AI/search requests send relevant user-provided content to the chosen service. No analytics, advertising, private-message access or Chrome browsing-history collection. Store categories and policy disclose local data as well.

Verification: automated tests, production UI fixtures and a real Flash text call passed. Installed extension pages were blocked by tooling; real X article transfer and every external search/image/login service were not revalidated in this release. Screenshots are actual production UI with synthetic demonstration content; promotional artwork is conceptual AI art, not fabricated UI.
