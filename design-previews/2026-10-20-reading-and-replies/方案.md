# 乔木 X 助手：阅读、作者信息与待回复

方案日期：2026-10-20。当前阶段是产品与交互设计；正式插件尚未修改。基于当前源码 `568e1a8`、用户提供的三张截图，以及真实 X 页面只读检查。

新增需求见配套方案：[Jev 判断、词汇规则、人工标注与服务器共建](判断与共建.md)。已纳入主帖与账号证据、标点／emoji、历史标注、Markdown/JSON 导出和协同过滤；所有新增模型效果仍待评测。

## 产品目标

让认真参与讨论的人做到三件事：快速了解作者，安静地阅读，把值得回复的帖子先收下，空闲时集中处理。

刷帖子时只增加必要信息；需要了解账号时打开资料卡；开始处理回复时进入工作台。收集、查询、备注和处理状态不依赖 AI，也不要求先配置模型。

设计取向：融入 X 的原生界面，系统中文字体、灰阶、少量状态色；视觉冒险度 3、动效强度 2、信息密度 6。功能契约：三秒内识别“作者是谁、是否值得继续读、如何稍后回复”，一击完成收集，失败可重试，误操作可撤销。

## 已有基础与实际缺口

| 部分 | 当前源码已有 | 需要改变 |
| --- | --- | --- |
| 回复判断 | 过滤阈值、自动折叠、AI / 真人标注、单条保留、作者名单 | 正常回复下面常驻一排图标和概率；应收敛 |
| 待回复入口 | 时间旁的星光 → 兴趣弹层 → 稍后回复 | 入口过深；打开弹层就触发兴趣模型请求，应独立一键收集 |

| 集中处理 | 打开原帖、评估、置顶、已处理、稍后再看、移除 | 缺少列表与详情并排、连续处理、撤销与清晰默认排序 |

| 成功回执 | 已有联系人回复成功观察逻辑 | 未关联待回复任务，也未充分核验原帖关系；不能直接称为自动完成 |
| 作者信息 | 可提取作者账号、昵称，已有联系人备注和主页评估 | 没有帖子关注数和头像卡增强 |

## 推荐的回复区

采用预览 B 的展示规则，自动过滤开启时采用 D 的折叠状态。A、C 用来比较操作直达和信息集中两种取舍，不建议把 X 整体换肤。

- **作者行：**昵称、账号、时间之后，显示 `986 关注`、`12.2k 关注`。这里是关注此作者的人数，即粉丝数，不是作者关注了多少人。卡片中使用“关注者”和“正在关注”区分方向。
- **关注关系：**紧接数量右侧，显示 `12.2k 关注 · 关注了你`；若双方均关注，显示 `12.2k 关注 · 互相关注`。对方没关注你或关系未知时省略，不展示“未关注你”。浅灰小字不抢作者名；窄屏把数量与关系作为一组换行。依据 `followed_by` 与 `following` 的两个明确布尔值，不用缺失字段推定关系。
- **收藏数：**有值时加在原生书签图标旁，沿用原图标、命中区域与收藏动作。不能新增第二个书签按钮。它代表平台报告的收藏次数，不等于内容质量，也不能看到收藏者名单。
- **右上角：**原生更多操作旁增加 Lucide `MessageSquarePlus` 图标，提示“加入待回复”。这是最高频的插件动作，始终可访问；不藏在 AI 菜单里。
- **底部操作：**按用户最新要求，隐藏和拉黑直接使用 Lucide `EyeOff`、`UserRoundX`，与判断入口组成紧凑操作组。悬停或键盘聚焦分别显示“隐藏这条”“在 X 拉黑作者”；文字不常驻。单套 tooltip，不同时叠原生 title 提示；图标按钮保留可访问名称。
- **判断入口：**仅标记模式下，超过用户现有阈值的回复显示轻微琥珀色 `AI 82%⌄`；低概率数字放进详情，普通回复默认安静。键盘聚焦、鼠标悬停可发现次要入口；触屏保留点击入口。
- **概率详情：**首行“疑似 AI · 82%”，随后是隐藏这条、判断有误保留、人工标注和账号操作。不生成模型没有返回的“判断理由”；实际目前只有结构化分数。
- **自动过滤：**遵守已有模式与阈值，严格高于阈值才折叠。采用 `@作者 · 疑似 AI 82%　展开　保留`。展开是临时查看，保留是这条回复的持久例外，两者不同。人工标注入口仍可到达。
- **拉黑：**图标与其他操作同为灰色，只有提示文字说明动作，止于 X 自己的确认。隐藏只作用当前条目且可撤销；不能因为一条回复的判断把整个作者当作机器人。
- **待判断／失败：**保留正文，不显示 0% 或“真人”。错误与重试在判断入口内；未配置模型时不在每条帖子下重复显示连接广告。

桌面优先同一行，正文宽度保持不变；窄屏把 `AI 82%` 收成可点击的 `AI` 小入口，完整分数在面板内。作者名沿用原生省略和换行；不缩小正文、不覆盖分享按钮、不横向挤压头像。最终位置以真实 X 不同布局的测量为准，放不下时优先收起次要分数文字。

## 头像上的信息：增强个人资料卡

可以放在头像悬停时出现，但应使用可以停留阅读的资料卡，而不是塞满文字的小 tooltip。

本次真实检查已经看到 X 自带的 HoverCard，内有简介、正在关注、关注者、关注关系与共同关注。优先保留这些原生内容，只增加一个紧凑补充区：

```
原生：头像、姓名、账号、简介、关注按钮
原生：628 正在关注     12,243 关注者
───────────────────────────
加入 X                 累计发帖
2018 年 5 月           3,420

我的备注
独立开发者，下次聊内容发布流程。
```

最多两项新的事实，加一条用户自己的备注。已有 KOL 评估可在“更多资料”里查看，并显示样本量与时间；悬停不自动发起评估。单条帖子的 AI 概率留在帖子层，收藏数也留在帖子层。

有人工历史时补一行“你的标注：AI 4 · 真人 2”，点击打开证据列表；未标注时省略。社区开启后另列社区摘要并说明分歧；不把人工历史混写成账号身份。备注仍只在本机，标注贡献另行主动开启。

交互规范：

1. 鼠标沿用 X 的头像悬停卡；指针移入卡片后可以继续阅读。
2. 头像点击仍打开主页。点击关注数提供键盘和触屏可用的资料入口，不改变头像本来的点击行为。
3. 点击式卡片可用 Escape、关闭按钮、外部点击退出；关闭后焦点回到触发点。只读悬停不夺取键盘焦点。
4. 若不能可靠增强 X 原生卡，就只保留原生头像悬停，并让“关注数”按钮打开插件资料卡。不能同时显示两个浮层，也不屏蔽原生资料卡。
5. 未知数据省略，真实 0 可以显示；完整数字在卡内可读。暂不计算粉丝真假、身份可信度等没有足够证据的结论。

本次读到的已加载数据包括粉丝／关注／发帖总数、注册时间、简介、关注与被关注关系。样本是 8 条帖子，不代表所有页面和所有账号都保证返回。取数应绑定当前帖子 ID 与作者身份；虚拟列表换人时立即清理旧数据。

## 待回复：三个连续环节

### 1. 收集时尽量没有负担

点击“加入待回复”后：

- 立即保存当前已加载的正文快照、作者、原帖链接、发布时间、加入时间。
- 保存成功才显示勾与“已加入待回复”，短提示支持撤销。保存失败保持未加入，并提供重试。
- 同一个登录账号下，按帖子 ID 去重。重复点击已加入项打开“查看队列／移出队列”，不能因二次点击无声删除。
- 想法可选：提示中提供“记一句思路”，不自动弹表单；也可稍后在工作台填写。
- 数据不足时保留可用片段并注明“收集时未展开”，不把截断文字当作完整原文。
- 手动再次加入已处理／暂缓条目时恢复到待回复，并保留备注；自动采集同条帖子不恢复已处理或已移除任务。

### 2. 工作台让用户快速进入回复状态

主入口在 X 侧栏“待回复 · N”，点击打开已有扩展工作台页面；插件弹窗也提供同一个入口。窄侧栏使用图标和数量，不新建一个常驻悬浮球。N 只统计主动任务中待处理的数量，不包含暂缓和自动提及候选。

桌面采用列表与详情并排；窄屏为列表 → 详情，返回恢复筛选和位置。

列表只显示决定先处理谁所需的信息：作者／关注数、正文两行、加入时间、置顶、有无回复思路。第一版默认置顶优先、其余最近加入，可切最早加入／原帖最新／关注者较多。排序可以表达用户的互动策略，但不能命名为“高价值作者”，也不默认由 AI 决定优先级。

详情显示保存的正文、必要上下文、原帖链接、发布时间、收藏时互动快照、回复思路。快照与当前实时数据明确区分，打开页面不会自动反复抓取。

主要动作只有“去原帖回复”；旁边是“标记已处理”，暂缓／移除／恢复收进低频操作。置顶固定在详情头部。处理一条后，列表原位补下一条，详情选中下一项；保留筛选和滚动位置。

“去原帖回复”打开 X 原帖，工作台留在原处。已有可复用的任务标签页时优先复用，不连续打开十几个标签；原生回复框定位只有在对象确认无误时才做。首版不复制一套 X 发帖编辑器。

回复思路是本机备注，不是已保存到 X 的草稿，不会自动插入、提交或发送。可逐步增设用户主动复制；后续若做原生草稿回填，必须单独验证原正文、光标和撤销。

### 3. 完成状态要说真话

首版沿用三个任务状态：

| 状态 | 如何进入 | 恢复 |
| --- | --- | --- |
| 待回复 | 用户主动加入；从其他状态恢复 | 可暂缓、已处理、移除 |
| 暂缓 | 用户暂时不想处理 | 手动恢复；首版不承诺到期提醒 |
| 已处理 | 用户主动标记 | 可撤销或恢复待回复 |

“已打开”“正在准备”只是临时浏览状态，不算完成。关闭页面、复制文字、点发送、编辑框清空都不能单独证明回复成功。

后续自动“已回复”必须同时具备：发起账号、原帖 ID、实际新回复 ID、回复作者和回复目标关系验证；保存可打开的回复链接与确认时间。失败、取消、账号切换、迟到或无法确认时保持待回复。现有联系人成功观察可以复用部分入口，但不足以直接给队列盖完成章。

自动提及收集作为独立来源“提及我的”。默认待回复展示主动任务；候选可一键加入。新用户可按需开启收集，已有用户的设置与历史记录保留，不用升级替他们改变偏好。

## 范围与实施顺序

**第一批：让这条日常工作流成立。**

- 回复区收敛、关注数、收藏数。
- 头像卡事实与已有联系人备注复用。
- 一键加入、持久状态回读、数量、去重与撤销。
- 工作台列表／详情、回复思路、排序、搜索、置顶、暂缓、已处理、恢复。
- 原帖跳转与队列位置保留，现有导出保留。

**第二批：在有证据后加入的便利。**

- 可靠的已回复自动确认与链接回写。
- 可选的“明天再看”等具体到期时间。
- 用户主动请求的回复准备辅助；不让它介入一键收集。

新增判断与共建按独立路径推进：证据结构与评测 → 本机词汇规则／标注导出 → 小范围服务器共建。与阅读和待回复分开验收，避免共享服务成为基本阅读的依赖。

首版无需云端账户、后台抓取、跨设备同步、定时批量回复或新模型服务。内容质量与互动帮助仍可使用原有按需能力，本次不新增一个模糊的“作者价值分”。

上述“无需云端”指阅读与待回复首版；用户新增的协同标注需要可选服务，其认证、撤回、去重和部署另见配套方案。已有本机标注与队列不因是否登录共建服务而受限。

## 实施边界

- 复用现有 `inbox`，不建立另一个相似收藏库。沿用账号隔离与帖子 ID；扩展 `note`、首次加入／更新时间、来源和完成来源，迁移保留旧数据。
- 新增明确的只读状态查询与单项变更广播；内容脚本只获得当前账号、当前已加载帖子所需的状态，不向网页暴露完整队列、私人备注或密钥。
- 备注与统计在扩展隔离世界读取。页面 MAIN 只读取当前已加载帖子的最小公开数据；数据视为不可信输入，限制类型、长度、数字范围和身份匹配。不把网页数据作为执行账号操作的指令。
- 只从当前已加载帖子取得作者与互动数据，不拦截认证、不读取 cookie、不请求私有 X API、不替用户逐个访问主页。读不到便省略。
- 头像卡变动、文章节点复用、切换账号和页面后清理旧控件与监听。正常展示不引起额外模型请求。
- 设计预览、源码完成、构建、已安装扩展运行、真实 X 行为与发布是不同交付状态。本文件和样机不宣称插件已更新。

预计涉及现有展示、数据层、后台消息、构建与测试，超过 8 个文件；适合拆成“阅读信息与入口”“队列闭环”两批可独立回退的改动。风险最大的部分是 X 原生资料卡结构和回复成功归属，应分别验收，不把它们捆成必须同时成功的前提。

## 验收条件

1. 同一真实 X 帖子插入前后正文宽度一致，原生回复／点赞／收藏／分享仍可点击；浅色、深色、长用户名及 390 px 无重叠和横向溢出。
2. 正常回复无额外整行诊断；高概率、折叠、展开、保留、未知、失败分别可读。不会因鼠标悬停时 X 重写 class 而露出折叠正文。
3. 头像卡无双层浮窗；鼠标移入卡片、触屏入口、键盘与 Escape 可用；资料不会串到被复用的作者。
4. 不配置模型仍能一键加入与集中处理；保存动作模型请求数为 0。单条重复加入、跨窗口同时加入不产生重复记录。
5. 收集 100 条后刷新仍完整；至少 1,000 条时分页和搜索正确。加入、移除、撤销、切号、迟到返回和写入失败不会误计数量。
6. 已处理／暂缓数据可恢复；自动提及不会复活已移除项。搜索、排序、翻页和返回保留位置。
7. 备注不会发给模型或进入 X 正文。原帖删除时保存的片段仍可读，界面明确外部原帖不可用。
8. 点击原帖、取消回复、发送失败都不自动完成；将来自动完成须有真实回复链接与目标校验，并通过多编辑框／多账号反例。
